# Notice renderer sections

The improvement plan's first large-function refactor moves notice rendering into named sections in `document_render.js`: item number/section/abatement/action/citation/due cells, historical due content and current date inputs, ordered rows, title/inspection header, mailing/revision block, table, copies, signer and historical finishing. Each section receives the current document and explicit render-local context or the existing renderer services; no new mutable registry, state, cache, format or authority is introduced. Service lookups still happen during rendering.

The renderer factory's size ratchet drops from 811 to 427 lines. The 446-line notice function and its 228-line row callback now fit the standard 80-line limit; both former notice complexity exceptions (55 and 75) are removed because the new functions fit the standard limit of 20. No new exception is added. Citation-face exceptions remain unchanged for separately reviewed work. The total JavaScript complexity exceptions fall from three to one, and size exceptions from 42 to 40.

All 69 exact authored historical/current print variants pass, including overflow/clipping/missing-copy mutation detection; R54 real Chromium extension layout/PDF geometry checks pass. The independent renderer, boundaries, unchanged report facts, ESLint and formatting checks pass. A one-off original-versus-current compilation compares 2,000 seeded notice outputs and service read/call/failure sequences across ten document types, nine historical authoring versions, both draft states and 544 interrupted paths; all match. The original source, driver and logs are retained outside source under `improvement-plan-2026-11-13/notice-before`, `check_notice_parity.cjs`, `notice-parity.log`, `notice-print.log` and `notice-extension.log`.

Existing print/legal/history fixtures and tests are unchanged. Full exact-head GitHub verification remains mandatory before delivery. No release identity change, packaging, deployment or City acceptance is part of this refactor.
