# Domain rules

These are the rules the program enforces now, grouped by feature. Rules confirmed by the product owner are marked as such; release-by-release history is in CHANGELOG.md and docs/history/.

## Authority and approved wording

Legal wording, ordinance interpretation, court schedules, numbering, authority, seasonal policy and language approval belong to the division. The mandatory-appearance hold remains enforced in Writer and helper until approved distinct defendant instructions are supplied. Historical frozen reprints remain unchanged. Current approved document and court wording (notice blocks, document bodies, court details, copies, instructions and contact) is data in app/assets/approved_language.json; change it only with the division's language approval (L5). Issued documents keep their frozen copies.

The owner approved a citation plea-instruction change on 2026-11-03: pleas may be entered via email, regular mail, the court’s website or fax; telephone is removed as a plea-entry method. Telephone pretrial-conference instructions remain. New/default court instructions use this wording, while issued documents retain their frozen instructions.

## Issued records and identities

Preserve issued snapshots, event/item/root/visit identities, action chronology, correction lineage, withdrawals versus compliance, deadline limits, initial notice/citation atomic publication and legacy readers. Device saving is not issuance; a filed marker is not PDF proof; an Outlook draft is not delivery. A pending publication confirms its retained request before another action. Every document keeps the authoring version it was issued with; earlier versions are unchanged and corrections render in the source's format.

## Inspection import

Inspection imports read the division's live DocumenGeneratorImport SSRS report as XML with the signed-in Windows user (helper `ssrs_reports.py`, `ssrs_fetch.ps1`; the direct SQL lookup was replaced on owner direction 2026-11-10 and the SSRS Excel file import was removed in R69). The import uses the inspection-type/status matrix in accela_import.js:

**Open cases by inspector (owner request 2026-11-02; live report 2026-11-10).** `helper/inspector_cases.py` renders the division's `OpenEnforcementCases_BI` report. Without a parameter it lists every inspector's open cases; the helper counts each `AssignedInspector`'s distinct cases for the inspector list (kept 30 minutes per share and settings; Refresh reads it again). One inspector's cases are rendered with the report's `Inspector` parameter using the name exactly as the report printed it, and every returned row must name that inspector. The inspector is identified by that name (the report has no user-ID column); a request for a name not on the current list is refused. The report owns the open-case rule and the names; the helper applies the exclusions, validation and verified due dates. `/inspector-cases/names` remains for compatibility and returns no names.

| Inspection type    | Statuses that decide a document                                                                                                                                                                           |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Initial Inspection | Official Notice, Citation, No Occupancy, Abatement Summary, Abatement Non-Summary                                                                                                                         |
| Reinspection       | CA Referral / City Attorney Referral, Compliance, Citation, Extension Processing, No Fee Extension Processing, No Occupancy, No Fee No Occupancy, Reinspection, No Fee Reinspection (Reinspection Notice) |
| CA Reinspection    | Compliance, Non Compliance                                                                                                                                                                                |

Completed and all unlisted results are refused. Never listed (owner rule): Scheduled, Pending, Completed, Inspection and No Violation results for every type, Reinspection and No Fee Reinspection results for every type except a Reinspection (owner request after R64: for a Reinspection they are listed and lead to the Reinspection Notice), Initial Inspection No Entry, Assist inspections, undated rows and inspections already used on the case. The refresh of an unissued draft's or worksheet's own inspection is not a use. Other type/status pairs are listed, greyed and not selectable, with their reason. Unknown statuses, unsupported types, missing actual dates and future dates cannot authorize an import. Blank times remain blank. A result status is not evidence that Document Writer issued a document; shared record identities independently prevent reuse. Existing unfinished work opens through Continue existing case. Several eligible results require an explicit choice. Snow Removal record category retains the MGO 10.28 route.

**Reinspection Notice (owner request after R64).** A Reinspection or No Fee Reinspection result of a Reinspection opens the worksheet and leads to a `reinspectionNotice` document: a primary follow-up of the recorded reinspection, header "REINSPECTION - Building Inspection Official Notice", the approved paragraph in `approved_language.json` (`documentBodies.reinspectionNotice`, identical for both statuses), corrected items ruled through with their confirmation date by the existing sentence and every other item listed outstanding. It never assigns, moves or removes a due date: each item prints the due date it already had (corrected items keep theirs), the date is shown as text and is not editable, past dates print as assigned, and the helper refuses an issued document whose due dates differ from its source or that has no outstanding item (`_validate_followup_outcomes`). A correction of a Reinspection Notice keeps every due date as well (`_validate_reinspection_notice_correction`). It is outside the referral workflow (refused on a case with the City Attorney), sets the case status Reinspection in both case projections and Reports, and is created only from the imported status. Authoring version 16 is stamped on the draft; the authoring-17 identity belongs to the release the owner assigns.

**Bundled order language approval (owner decision 2026-10-31).** The bundled library entries that were marked draft and have an ordinance section (123, including three whose section was filled in from the supplied MGO text and the library's sibling entries: Unsecured Vacant Building 27.085(2)(a), Smoke Alarms 27.05(2)(w), Plumbing work without required approval 18.08) are approved for selection as standard entries (`p` is no longer `draft`; `approval` records the decision; the catalog manifest `draft` flag follows). No catalog review event is recorded for them, so they appear under Approved and standard, which is the default scope of Browse language and the picker (owner decision 2026-11-01), and not under the narrower Approved language scope. Seven entries remain draft with no section (both carbon monoxide alarm entries, Occupancy Exceeds Permitted Use, Required permit inspections, Historic exterior work approval, Sleeping room without required egress, Unapproved room use); the picker and the helper refuse them until the division supplies a section and records a review. Citations in the library carry no trailing period after a numbered subdivision (for example 27.05(2)(g)1); the pricing code adds it back when it matches the schedule.

**Order-language search and grouping (owner direction 2026-11-10).** Consolidated Order Language replaces the earlier checklists: the picker and Browse language list it first and label the others as earlier checklists, without removing them. An ordinance search (`language_search.js`) matches an entry only when it cites that section or a narrower part; parent, sibling and broader sections are related and folded behind Show related sections; digits in wording never match. Status badges appear only on Review catalog. See ORDER-LANGUAGE-PICKER.md.

## Notices, items and deadlines

New notices begin with no automatic item deadline. At most three distinct outstanding-item dates are permitted by the existing rules. Physical visits and their item findings are distinct from document actions. No-access findings are not compliance. Withdrawn items retain their reason and identity. Private language edits survive removal/reselection; reviewed-version adoption is explicit; issued wording stays frozen.

## Extensions

Owner rules: new Best Interest and Vacancy Extensions cover every uncorrected item with no selection, no safety confirmation and no signer block. Best Interest due dates follow the normal Extension rules (the worksheet's Next due date, editable in Violation items). Vacancy prints no due date for uncorrected items and needs a review inspection at least seven days after mailing. Drafts in earlier formats keep them; only explicit adoption moves an unissued Best Interest draft to the current format. The existing Best Interest safety-exclusion checkbox remains for authoring-15 drafts, which need that explicit confirmation but no separate safety-basis narrative. Older formats and other families retain their requirements.

## Histories and referrals

Owner rules: show the inspections that actually observed each item, beginning at that item's first observation, including later-added items. Days Outstanding stops at correction; outstanding items end at their latest recorded observation. Carried compliance is not a new observation. No date is inferred from mailing/issuance or unrelated case visits. New referral, referral-update and compliance documents print every note under the violation, corrected items included. Compliance letters retain item-specific observation histories and explicit Abate values. A referred case allows only Update for Case Referral or Compliance Letter; corrections of earlier documents remain possible.

## Citations and pricing

Required citation copies remain Court, Agency, Inspector and Defendant, with approved distinct content; previews and PDFs must contain all four distinct copies per charge (owner rule). Pricing preserves determined locks, counted history, approved basis provenance, required measurements and unchanged-correction prices. Correction money formatting never changes stored units or pricing. Manual authority is separate from the mandatory wording hold. Snow uses its existing site/season rules and no ordinary repair deadline. Do not change policy to bypass a readiness check.

**Violator contact (owner request after R66).** A Copies entry may have the type Violator (`ccList` entry with `kind: "Violator"`, at most one per case). On every non-snow document it replaces the property owner as the main contact in the mailing address block and as the citation defendant and address; a snow removal case (`snow-10.28`) ignores it. The owner is printed under CC by default and the case flag `copyOwner: false` removes it (the flag is stored only when turned off, so re-ticking the box leaves no correction change). With a Violator set, the mailing-block readiness checks lead to Recipients. The Violator is the pricing respondent for repeat offenses and the registered-agent rule (repeat counts for `site` and `site-season` windows, for example MGO 37.07, still match on the property through `same_site`, not on the respondent key; only the time windows use `defendant_key`) (`defendantKey` in citation_policy.js, mirrored by `defendant_key` in helper/citation_pricing.py); the case summary and Reports keep the owner key (`respondentKey`). Frozen documents capture the whole case, so the Violator and flag freeze with each issued document. No case-record version was added: the helper rewrites saved cases at schema 5, so installs that predate the feature print the Violator as an ordinary copy and use the owner as defendant until updated (acceptance SVIO-4). The mailing block is read-only while a Violator is set. A Violator row with no name, street or city is dropped when Recipients is closed (owner decision 2026-11-01, as a blank ordinary copy is ignored); a partly filled Violator row is still refused with a message naming the Violator, and the readiness check (`validateAndStandardizeAddresses` with `normalize` false) still reports a blank one left in a saved draft.

**Confirmed owner decisions (2026-11-01).** A correction cannot add new items (its items are those of the corrected document); and a case that exists only as an unissued draft does not appear in Open cases by inspector, which reads the verified shared case summaries and lists those whose status is not Closed or Withdrawn (a snow case also closes on its closing filing). Do not report either as a defect.

## Reports

Reports accepts only verified case bytes matching summary sourceRevision, and only a summary whose reportable fields equal the helper's projection of that verified case (helper/case_projection.py, the exact mirror of summarize()); legacy, stale, duplicate, unreadable, unproven or non-matching projections remain visible as excluded coverage. The case file is the authority: a rebuild rewrites summaries, never cases or integrity history. Current table, CSV, workbook and report print use the same row ordering. Cached review metadata is labeled and cannot bypass publication validation.

**Missing case file with a retained registry entry (owner decision 2026-11-03).** A case whose file was deleted for good leaves its number in the migration registry (and perhaps an external anchor); before this decision the save was refused forever. Now `case_integrity.automatic_restart` lets the next save start a new history without administrator approval, as a weaker, tamper-evident rule instead of a tamper-blocking one: nothing retained is deleted or rewritten; the new genesis carries `administrativeRecovery` with `automatic`, `missingCaseFile`, `priorAnchoredCommitHash` and `priorGenesisHashes`; the registry entry is flagged `administrativeRecovery`; verification accepts the older anchored head only through that note; and `verify_record` returns `historyRestarted` with a label ending "history restarted <date> because the case file was missing". If any entry for the number is on the share but cannot be used (a link or reparse point), nothing is restarted and the save is refused, so a second history never hides the first; a pending integrity transaction also refuses. A present file whose genesis differs from the registry still raises `GENESIS_CONFLICT`.

An interrupted automatic restart resumes its exact retained transaction on an ordinary save retry, including interruptions before case publication, before registry publication, or before transaction removal. The original restart genesis is reused and the registry is not duplicated. Recovery of a present, damaged case still requires explicit administrator approval.

**Sort by due date (owner request 2026-11-03).** On a new Official Notice draft (`structEditable`, the same condition as reordering items), `#btn-sortdue` beside Apply date sorts `d.items` through `deadline_assignment.orderByDue`: soonest due date first, inside each run of neighbouring items that share the same `group` heading text (a notice with no headings is one run), invalid or missing dates last, equal dates in their earlier order. Headings are not moved, items are renumbered like a manual move, and Undo restores the earlier order unless the draft changed. The reinspection worksheet has no Sort button.

**Case bubbles and inspection facts (owner request 2026-11-03).** Each open case is a `button.import-inspection.open-case` (the existing inspection-result bubble style, no new stylesheet rule): case number and address on a no-wrap line, the description below, `is-selected` and `aria-pressed` on the case being looked up or reviewed. `open_case_list.pick` runs on every selection: it stops a running lookup (`cancelCaseLookup`), clears `editor.state.acc`, `editor.WORK.acc` and the earlier lookup error, records `openList.picked`, fills the lookup number and runs `findDatabaseCase`; nothing blocks a new selection. `inspectionSummary` shows the inspector on the first line and a second `.import-facts` line with the type, date and status, values only (the `data-import-field` attributes remain for tests).

**Built-in excluded staff (owner direction 2026-11-03).** `inspector_cases.DEFAULT_EXCLUDED` (`Alice%Duncan%Graves`, `Gregg%May`, `Jessica%Price`, `Phil%Grupe`; case-insensitive, `%` for any text, matched against the user ID or full name like the administrator's entries) is always applied, and the administrator's `Case Lookup/excluded-inspectors.json` entries are added to it. A person first shown by user ID is removed when the name step resolves them (the helper's `excluded` list), and their case list is refused.

**Due date column on open cases (owner request 2026-11-03).** `inspector_cases.open_cases(root, inspector, case_dir)` adds `dueDate` to each case from that case's own Reporting Index summary (`due_dates`: only the listed cases' `<case number>.json`, read with the plain-file reader, at most four at a time, any unusable file giving none). `next_due` is the earliest `due` among the summary's `violations` that are not done or withdrawn; a summary's violations carry the due dates of the last live document that has items (`facts.last_items` in the projection), so the date is that last issued document's soonest outstanding deadline. The response also says `dueDates` false when the case folder cannot be read. The helper sorts cases with no due date first (in the database's order), then ascending by date, so past-due dates lead the dated ones. The bubble shows the date as month/day/year under a Due label in the `.open-case-due` column (`writer.css`, reviewed in SCREEN-VISUAL-REVIEW.md).

**Discarding a case's only draft (verification follow-up 2026-11-04).** `discardDraft` also clears the case's copies, email recipients and owner-copy choice (`ccList`, `emails`, `copyOwner`) when the case exists only as that draft: nothing issued, no events, no saved checkpoint and no other draft or worksheet. A new notice for the same case then starts with the default recipients. Any case with a document, event, checkpoint or other draft keeps its recipients.

**Worksheet unavailability reasons.** `eligibility` in `new_documents.js` no longer says only "No outstanding items for this action." For a worksheet where no item has a result yet it asks for a result on every violation item; where every item is corrected or withdrawn it says so.

**Recipient mailboxes and manual violation levels (owner request 2026-11-04).** CC and Violator fallback validation accepts a numbered street or a PO Box identifier; the optional parser is not required. City/state/ZIP and names remain mandatory, nonmutating readiness and validation-before-normalization remain, and registered agents retain their existing street/explicit-parser rules. Violation level selects Automatic or ordinals 1/2/3 through the existing tierOverride/tierOverrideSource pricing path. A manual choice still requires its recorded source; the configured schedule supplies the base and assessments, including open-ended final tiers. Automatic clears both override fields before refreshing history-based pricing. Issued, pending-save and retained historical-deposit records cannot be changed by this selector. No schema, release or approval-authority change is introduced.

**Reinspection Notice readiness (MCR-009, 2026-11-05).** `document_readiness.js` treats a `reinspectionNotice` as keeping its assigned due dates (`readinessKeepsDates`): the past-due, more-than-six-months and short-window checks that police a newly assigned date do not apply, so a notice whose outstanding items are past due or due today can issue. A missing or impossible retained date still blocks; the helper still refuses any changed date; Official Notices and Extensions keep every future-date rule.

**Code-review corrections at the helper (2026-11-05).**
- *Open-case due dates (MCR-002).* `inspector_cases.due_dates` returns `(state, date)` per listed case: `due` only from a Reporting Index summary that names the current revision of the single case file, whose integrity verifies (`case_integrity.verify_record`) and whose projection equals the summary (`case_projection.mismatched_fields`, current summary format only), the same authority Reports uses; `none` when the case was never saved to the share (no case file, no summary) or has nothing outstanding; `unknown` for anything that cannot be confirmed (missing, stale, orphaned, unreadable, earlier-format or mismatched summary). `open_cases` adds `dueState`; the list sorts `none`, then dated ascending, then `unknown`; the bubble shows Not confirmed for `unknown`.
- *Exclusions on case requests (MCR-003).* `open_cases` checks the requested ID against every name the helper holds for it (`_known_names`: the checked workflow list's name and the deferred name lookup's), so a full-name exclusion refuses the case list (403) whether or not the deferred lookup ran.
- *Ordinary visit dates (MCR-006).* `validate_visit` refuses a new ordinary visit dated after the city day it is recorded; historical events are revalidated without the bound, as for occupancy-release visits.
- *Mandatory-appearance draft backups (MCR-007).* `server.validate_draft_deposits` accepts an empty deposit only for a citation whose scheduled charge resolves to the mandatory rule and carries `mandatoryAppearance: true`; every other citation still needs a positive deposit. The issuance hold is unchanged.
- *Deadline spacing (MCR-008).* `validate_authoring` (new writes only) refuses distinct outstanding due dates less than seven days apart on a notice, extension or citation (`_validate_due_spacing`, snow excluded); a correction may keep a pair it already had, but a changed date must respect the spacing.
- *Deployment preparation (MCR-013).* `prepare_deployment.py` verifies the extracted release (manifest, sizes, SHA-256, exact inventory, safe paths outside the operational folders) before touching the target; replaced program files are kept under `replaced-by-this-release` in the dated folder beside the target with the retired items; a failed copy or final verification puts the previous deployment back.

**Code-review corrections in the Writer and Reports (2026-11-05).**
- *Case removal (MCR-001, MCR-004).* `removeCase` reads ownership before removing anything: it discards the record forms (record note, withdrawal review, follow-through) of the removed case's documents and keeps other cases' forms, and clears the selected worksheet and retained walkthrough when they belong to that case (walk context `case|visit|document`). `caseUnsaved` reports "unfinished record notes", so Remove safe cases keeps such a case.
- *Import-only recovery (MCR-005).* Restoring an import-only backup brings back only the import's fields (`acc`, `entry`) into the current working context; other cases' record forms and walkthrough progress stay, in memory and in the persisted draft bundle, and the backup's own stale forms are not restored.
- *Snow cases as of an earlier day (MCR-010).* A snow case is in the Reports model while it has, or ever had, an issued citation; as of a date it counts if a citation was effective that day (`reportSnowNoticeIncluded`), so a later withdrawal does not change an earlier count. Current reports still need a current citation.
- *Repeat cases by owner (MCR-011).* Still open excludes a snow case closed on filing (`closedOn`), as All cases does.
- *Timeline (MCR-012).* `document.voided`, the stored event for Withdraw, is in the Withdrawn filter and its CSV export.

**Import window (owner request 2026-11-05).** Selecting an open case or choosing Find Case Inspections opens the import window, drawn in the page's dialog layer (`importWindowHTML`, rendered by `overlayHTML` on the Import screen while a lookup runs, a lookup failed or a case is retrieved; the page behind it is inert). It shows the running lookup, the failure, or the existing review panel with its confirmation; a single eligible inspection is no longer imported automatically (`openLookupResult` only reports it, and the window says one inspection is available), so nothing is imported until the inspector confirms it. Exit (`acc-exit`) cancels a running lookup, clears the retrieved case and its message and keeps the typed number; Save draft & return to Workspace moves into the window while it is open. The retained `accela_import_reference.txt` carries the same lookup-card wording and the removal of the automatic acceptance.

**Workspace cleared on close (owner request 2026-11-05; owner choices: clear all, warn first; Exit and next start).** `session_close.js`. Exit Document Writer shows `exitClearHTML` (the workspace is cleared; unfinished work from `caseUnsaved` and an import in progress is listed with Download workspace backup and a required `clearUnfinished` confirmation, checked by `exitClearConfirmed` before the shutdown request); after the helper confirms it stopped, `exitWorkspaceClear.clear` removes every case with `removeCase` (a case with a pending save confirmation is kept), the import work and the editor selection, saves the device bundle and records the session closed. At start (`startSession`, after pending saves are flushed and before the start screen) a session recorded open under a different helper instance (`meta[name=docwriter-instance]`) ended without Exit: saved work is cleared at once; unfinished work is offered for clearing in a dialog and kept until confirmed. A reload under the same helper instance, a first start and a start without a helper instance clear nothing. Queued shared saves (`PENDING`) and the PDF outbox are never cleared.

**Review corrections after R74 (2026-11-06).**
- *Name exclusions on case requests.* `open_cases` reads the checked workflow list again when it has expired or was never loaded (`_known_names` → `_list_answer`), so a full-name exclusion no longer depends on a recent picker visit; if the list cannot be read the request is refused rather than guessed.
- *Clearing at start never blocks startup.* `startSession` catches any failure (a refused device save, a storage rejection) and keeps the work; the inspector is told once the screen is up. Before this, a refused clear threw into `bootStorage` and paused the whole Writer.
