# CI artifact upload and gate recovery

Each existing artifact upload has at most three attempts using the same pinned actions/upload-artifact commit, name, path, retention and missing-file policy. Only the first two upload steps may continue after failure; retries run only after the prior upload fails and never after cancellation. A retry overwrites a possibly finalized but unacknowledged artifact of that same name in that same workflow run. All attempts failing fails the job. Verification/build/test steps and jobs never continue after failure. Failed-stage diagnostics retain their separate names; nothing caches passing test results.

Full gate keeps its required-needs success guard. It alone adds Actions read permission (plus contents read); producer/Windows jobs keep their existing read-only permissions. Its --assemble-github entry point is restricted to GITHUB_ACTIONS=true and GITHUB_JOB=full-gate. The resolver authenticates the current repository/run/attempt, exact checked-out source and workflow path through the GitHub API, with complete bounded pagination. It selects the nearest attempt containing producer jobs and requires exactly one completed successful regression check and browser check from that same attempt/head/run, plus exactly one unexpired authenticated ZIP for each. Partial/failed/skipped/mixed producers do not fall back to older success. GitHub can clone successful producer jobs into a gate-only attempt with new job IDs, creation times and attempt numbers, while retaining their original execution times and steps. The resolver authenticates each attempt's start time and requires both carried jobs to have completed before it, then requires their execution identities/times/steps to match the original successful pair. Mixed fresh/carried jobs, changed executions and failed/skipped producers refuse reuse. Empty producer lists remain supported. Selection is bounded to 20 attempts and retains the original producer job IDs plus the carried-job IDs in its receipt.

Both ZIP sizes/digests must match authenticated metadata before extraction. Unsafe/duplicate paths, links, special files, excessive file counts or expansion are refused into fresh temporary staging. The GitHub API token is scoped to api.github.com; no credentials are forwarded to the signed blob-storage URL and further redirects are refused. Temporary inputs are removed after assembly or failure.

The existing assembler then rebuilds production output and performs every original source/clean-head/runtime/toolchain/browser-version/sealed-file/complete-suite/projection/print/browser/axe check. The canonical verification/repository/regression/browser evidence and packaging contracts are unchanged. stage-evidence.json additionally records producer selection and the assembly identity; identity still names the common producer run/attempt. An earlier attempt number or local receipt alone cannot enable this path. The ordinary local --assemble continues to require its current identity and refuses earlier-attempt artifacts.

Use GitHub's rerun of Full gate after an upload/download/service interruption only when the complete producer pair already succeeded. If either producer lacks a complete successful artifact, rerun all jobs. Missing or expired evidence is a blocker, never permission to skip a suite. No fast-mode result can authorize merge/release. Keep measured work serial and both existing workers unchanged. A persistent provider outage can still prevent evidence retention; three upload attempts do not promise otherwise.

Targeted resolver tests cover complete same-attempt/current and gate-only prior pairs, cloned successful jobs and repeated gate-only attempts, mixed/fresh or modified carried executions, malformed/timezone-free/reversed/cross-boundary execution times, source/run/workflow/attempt binding, failed/skipped/missing/duplicate/mixed producers, artifact metadata/digest/size/path/link/expansion failures, read-only selection, scoped API credentials and redirect handling. Existing stage/lifecycle tests and workflow failed/cancelled/skipped guards remain. Workflow tests independently require identical retry payloads, exactly three attempts and a fatal final failure. Full exact-head CI and an actual gate-only rerun must be checked before declaring delivery complete; no synthetic-only CI acceptance claim.
