# Code ownership

Browser app/modules: app_entry and reports_entry start their core modules; state owns mutable stores; app_core owns service composition, shared state setup and explicit event-registration order; *_events modules own feature callbacks/actions through scoped service interfaces, with event_registration owning per-target duplicate protection; document_types owns stable document/event metadata and approved wording references; document_rules owns explicit authoring/item predicates; writer_queries owns live state/frozen-source queries; presentation_format owns text/selector markup; record_values owns JSON snapshot copying, stable ordering and case comparison values; case_migrations owns deterministic legacy migration; case_file_rules owns shape/identity/history validation and merge/name rules; case_projection owns replay, item carry-forward and report-summary calculations; record_sources owns explicit frozen/correction case-source resolution; calendar owns existing date arithmetic; mailing_rules owns mailing facts and state codes; accela_report owns the pure report reading (report columns, type/status rules, XLSX reading and report parsing); accela_import owns the independently composed createAccelaImport service (candidates, the review plan and panel, the direct database lookup and acceptance); core supplies its named lazy dependencies and exports the actual instance functions; reinspection owns the reinspection worksheet, its checks and the one-item walkthrough; editor_screens owns the createEditorScreens service (editor screens, readiness/review, item order, newDoc and sheet/overlay/dialog refresh); core composes and exports its actual instance functions; app_screens owns independently composed render/renderKeep; workspace_screen owns the Workspace list/reveal/focus, case_status owns live caseState, citation_history owns priorCitations, language_views owns language screen/picker adapters, screen_overlays owns modal/overlay HTML and ui_icons defines icons; workspace_shell, citation_drafts, visit_recording, working_papers, recovery_ui, record_history, catalog_forms, language_catalog, reports_services and reports_screens own exported functions; desktop_exit owns the Exit Document Writer review and request, and helper_stopped the stopped state shared by Writer and Reports. Focused domain services own snow, pricing, catalog, initial citations, address parsing, navigation, new documents and proof. navigation, language_actions, citation_pricing, deposit_step, initial_citations, snow_cases, administration, address_parser and new_documents receive scoped lazy UI/peer interfaces from app_core and remain independently loadable. test_fixtures receives scoped callbacks only in the fixture build; affected-row selection belongs to the composed new_documents service. document_render owns the independently loadable createDocumentRenderer factory and its notice/document/citation templates; core supplies its scoped dependencies and exports its actual documentHTML/citationFaces functions. app_view_contexts owns three scoped context constructors for saved work, the Workspace queue and language discovery; core composes/exports their actual instance builders and preserves lazy service identities. document_pagination owns the independent physical-layout constructor; core composes/exports paginate. reinspection owns docFromReinspection, and editor_screens owns refreshSheet, syncChip, refreshOverlay and enhanceDialog. Presentation modules adapt existing facts without owning persistence.

Helper: server owns loopback transport, rendering and the guarded shutdown route with its in-memory active-work count; case_store also counts the file locks this process holds; case_store owns case locks/commits; case_integrity owns proof/migration/anchor verification; citation_pricing owns prices; artifact_store owns original bytes; reporting_reads owns bounded read scheduling; case_projection owns the reporting projection of a verified case (the exact mirror of case_projection.js through the case_summary_adapter.js summarize adapter, reading build/generated/projection_tables.json); case_lookup owns fixed SQL transport; admin/workflow modules own their established validations; verified_update owns manifest-checked updates (sizes, SHA-256, file set, downgrade); desktop_launch owns the windowless desktop start (launcher log, dialogs, shortcut, hidden helper, the one place that builds the authenticated app-window URL) and runtime_paths.no_window the console-free flags every helper child process states; helper_session owns bootstrap; trusted_connections owns outbound trust; render_security owns resource/CSP rules.

Tools: direct-source build and version synchronization, deterministic browser build, policy compiler, tests, verification and packaging (deploy_manifest writes the file manifest). Tests: unit, production browser and retained fixtures. Policy: approved effective-date sources and compiler. Staff docs: manual and workflow/install/case/printing guidance. Developer docs: current architecture/rules/testing, the living acceptance and readiness records and the current release review; docs/history holds earlier releases. CHANGELOG records concise release history.

The behavior-preserving cleanup scope, dependency layers and following increments are in [MODULE-CLEANUP.md](MODULE-CLEANUP.md). `tools/module_graph.cjs` inventories browser dependencies; audit_module_boundaries keeps foundations outside UI cycles.
