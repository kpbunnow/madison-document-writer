# Code ownership

Browser app/modules: app_entry and reports_entry start their core modules; state owns mutable stores; court_and_deposits, workspace_shell, case_files, reinspection_walkthrough, issuance_and_corrections, draft_recovery, language_catalog, case_timeline, inspection_import, document_render (notice, document and citation-face HTML), document_pagination, reports_services and reports_screens own exported functions. Focused domain services own snow, pricing, catalog, initial citations, address parsing, navigation, new documents and proof. Presentation modules adapt existing facts without owning persistence.

Helper: server owns loopback transport and rendering; case_store owns case locks/commits; case_integrity owns proof/migration/anchor verification; citation_pricing owns prices; artifact_store owns original bytes; reporting_reads owns bounded read scheduling; case_lookup owns fixed SQL transport; admin/workflow modules own their established validations; verified_update owns manifest-checked updates (sizes, SHA-256, file set, downgrade); helper_session owns bootstrap; trusted_connections owns outbound trust; render_security owns resource/CSP rules.

Tools: direct-source build and version synchronization, deterministic browser build, policy compiler, tests, verification and packaging (deploy_manifest writes the file manifest). Tests: unit, production browser and retained fixtures. Policy: approved effective-date sources and compiler. Staff docs: manual and workflow/install/case/printing guidance. Developer docs: current architecture/rules/testing, the living acceptance and readiness records and the current release review; docs/history holds earlier releases. CHANGELOG records concise release history.
