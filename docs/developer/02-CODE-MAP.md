# Code ownership

Browser app/modules: app_entry and reports_entry start their core modules; state owns mutable stores; app_core owns service composition, shared state setup and explicit event-registration order; *_events modules own feature callbacks/actions through scoped service interfaces, with event_registration owning per-target duplicate protection; document_types owns stable document/event metadata and approved wording references; document_rules owns explicit authoring/item predicates; writer_queries owns live state/frozen-source queries; presentation_format owns text/selector markup; record_values owns JSON snapshot copying, stable ordering and case comparison values; case_migrations owns deterministic legacy migration; case_file_rules owns shape/identity/history validation and merge/name rules; case_projection owns replay, item carry-forward and report-summary calculations; record_sources owns explicit frozen/correction case-source resolution; calendar owns existing date arithmetic; mailing_rules owns mailing facts and state codes; accela_import owns the independently composed createAccelaImport service (report columns, type/status rules, XLSX reading, report parsing, candidates, the review plan and panel, the direct database lookup and acceptance); core supplies its named lazy dependencies and exports the actual instance functions; reinspection owns the reinspection worksheet, its checks and the one-item walkthrough; editor_screens owns the createEditorScreens service (editor screens, readiness/review, item order, newDoc and sheet/overlay/dialog refresh); core composes and exports its actual instance functions; app_screens owns the Writer screen dispatcher (render), the shared picker, modal and overlay HTML and the case list; court_and_deposits, workspace_shell, case_files, issuance_and_corrections, draft_recovery, language_catalog, reports_services and reports_screens own exported functions; desktop_exit owns the Exit Document Writer review and request, and helper_stopped the stopped state shared by Writer and Reports. Focused domain services own snow, pricing, catalog, initial citations, address parsing, navigation, new documents and proof. navigation, language_actions, citation_pricing, deposit_step, initial_citations, snow_cases, administration, address_parser and new_documents receive scoped lazy UI/peer interfaces from app_core and remain outside the retained Writer cycle. test_fixtures receives scoped callbacks only in the fixture build; affected-row selection belongs to the composed new_documents service. document_render owns the independently loadable createDocumentRenderer factory and its notice/document/citation templates; core supplies its scoped dependencies and exports its actual documentHTML/citationFaces functions. app_view_contexts owns three scoped context constructors for saved work, the Workspace queue and language discovery; core composes/exports their actual instance builders and preserves lazy service identities. document_pagination owns the independent physical-layout constructor; core composes/exports paginate. reinspection owns docFromReinspection, and editor_screens owns refreshSheet, syncChip, refreshOverlay and enhanceDialog. Presentation modules adapt existing facts without owning persistence.

Helper: server owns loopback transport, rendering and the guarded shutdown route with its in-memory active-work count; case_store also counts the file locks this process holds; case_store owns case locks/commits; case_integrity owns proof/migration/anchor verification; citation_pricing owns prices; artifact_store owns original bytes; reporting_reads owns bounded read scheduling; case_projection owns the reporting projection of a verified case (the exact mirror of case_projection.js through the workspace_shell.js summarize adapter, reading build/generated/projection_tables.json); case_lookup owns fixed SQL transport; admin/workflow modules own their established validations; verified_update owns manifest-checked updates (sizes, SHA-256, file set, downgrade); desktop_launch owns the windowless desktop start (launcher log, dialogs, shortcut, hidden helper, the one place that builds the authenticated app-window URL) and runtime_paths.no_window the console-free flags every helper child process states; helper_session owns bootstrap; trusted_connections owns outbound trust; render_security owns resource/CSP rules.

Tools: direct-source build and version synchronization, deterministic browser build, policy compiler, tests, verification and packaging (deploy_manifest writes the file manifest). Tests: unit, production browser and retained fixtures. Policy: approved effective-date sources and compiler. Staff docs: manual and workflow/install/case/printing guidance. Developer docs: current architecture/rules/testing, the living acceptance and readiness records and the current release review; docs/history holds earlier releases. CHANGELOG records concise release history.

The behavior-preserving cleanup scope, dependency layers and following increments are in [MODULE-CLEANUP.md](MODULE-CLEANUP.md). `tools/module_graph.cjs` inventories browser dependencies; audit_module_boundaries keeps foundations outside UI cycles.

Reports composition: reports_services.createReportsServices owns reads, model calculations, saved views, handoff, CSV/print and render; reports_screens.createReportsScreens owns screen/map/table/workbook output; reports_view_contexts.createReportsViewContext supplies the existing presentation context from live state. reports_core composes their exact named lazy dependencies, retains report definitions/state/startup/listener order and exports actual instance functions. deposit_schedule retains its original three listeners with explicit render/escape adapters. No Reports module imports back into core or a peer owner.

language_catalog.createLanguageCatalog owns catalog review/selection/adoption, shared-case comparison and preflight, conflict actions, guarded workspace patches and the retained safety/health/lock/workflow/search tools. app_core supplies its named lazy UI/storage/peer adapters and exports actual instance functions. The owner imports no UI or persistence orchestration module; existing storage and integrity operations remain in their supplied adapters.

reinspection.createReinspection owns worksheet/walkthrough context and focus, outcomes/undo, readiness/check targeting, deadlines, the reinspection screen and follow-up creation. Core composes its named lazy dependencies and exports actual instance functions; existing persistence, pricing and history operations remain in the supplied owners.

case_activity.createCaseActivity owns remindersDue/remindersPanel, reminder settings/draft presentation, filtered/sorted timeline rows and timeline presentation. timelineCategory is a pure export. Core supplies six named lazy dependencies and exports actual activity instance functions; workflow_events retains preference persistence, CSV/JSON export actions and the helper call for an explicitly requested email draft. The former mixed case_timeline module is retired.

calendar also owns validISO/parseDate/parseTime with their existing input semantics. inspection_facts directly exports inspAt, inspectionIdentity, sameInspection and inspectionUsed. Identity comparison is pure; document inspection-date selection and reuse checks query current workspace facts through writer_queries, preserving frozen/correction precedence and all retained document/visit evidence. These are not UI services or publication authorization. Consumers import their defining owners; Accela import no longer routes these seven calculations/queries through core callbacks.

pdf_artifacts directly exports pdfTransferState/independentArtifact and composes showOutbox/selectedOutbox/printOutbox/refreshArtifactLocations through five named lazy inputs: navigation, A11Y, helperJSON, toast and render. Core exports actual mutable operation bindings, while callers import the direct queries from their defining owner. The authenticated transport still reads retained original bytes; helper validation, transfer event actions, immutable filing and publication remain in their established owners.

writer_handoff.createWriterHandoff owns markWriterReady/markWriterFailed/writerOpenReportedCase/initWriterHandoff. Core supplies six named lazy dependencies and exports actual mutable operations. case_files retains locking/restoration and invokes channel initialization/readiness markers at the existing points; core retains the readiness promise and stable channel name. The owner imports only shared case-number normalization, case-file shape rules and WriterState. Preflight, storage/helper authority and Reports-side handoff remain in their existing owners.

deadline_assignment directly exports dueDateSpacingConflicts/dueSelectedText and live dueContext/activeDueTarget queries. Its createDeadlineAssignment factory owns planBulkDue/showBulkDue/updateDueIndicators/duePanel/assignDue through seven named lazy inputs. Core exports the actual mutable operations; callers use defining query exports directly. due_date_events retains listener/undo/save behavior and workflow_events retains durable batch patching; these do not become storage or publication operations in the new owner.

workspace_tasks.createWorkspaceTasks owns read-only workspace task groups through fmtDate/hasSetupWork/depositComplete adapters. Core exports its actual mutable workspaceTasks function; app_screens consumes that instance. The task owner uses current record/artifact/query facts and retains caller-supplied row/status snapshots. depositComplete remains with the citation workflow and delegates its unchanged fault calculation, without copying policy into presentation.

citation_workflow.createCitationWorkflow owns depositComplete/initialCitationBody/citationDepositFault/editCitation/commitCitationEdits/authoringChecks/citationReview. item_selection.createItemSelection owns toggleLibraryItem and private wording/cache/identity retention. Core supplies 16 and two named lazy inputs respectively and exports actual mutable functions; peer callers import those composed bindings. Pricing, administration, charge basis and deposit helpers retain their existing authority, and events/persistence/publication remain outside these owners. Both load independently and stay outside the seven-module Writer cycle.

record_commit.createRecordCommit owns the shared commitAmendment request/confirmation operation through 11 named lazy adapters: toast, saveDrafts, caseFile, COMMITTED, helperJSON, mergeCaseEvents, project, rememberSaved, idbSet, writeSummary and render. Core composes it after workspace task presentation and before document rendering, exporting the actual mutable function. Publication/correction/recovery callers use that instance. Construction performs no service/state/DOM reads or I/O and installs no listeners. The original function body is preserved apart from dependency access, including durable pending-save-before-request ordering, exact idempotency/group/correction events, definitive versus uncertain failures, later-edit preservation, projection/summary/pending cleanup and busy-state release. Helper validation, storage, projection, PDF receipts and publication eligibility retain their existing authority. This is an adapter boundary, not a pure calculation or a new transaction guarantee.

publication_preparation.createPublicationPreparation owns lifecycleChecks/makePublication through nine lazy inputs and direct current inspection/record queries. publication_workflow.createPublicationWorkflow owns publishDocument/publicationPanel and private publishOnce through 17 scoped adapters, retaining the per-draft guard in its single composed instance. Core composes them after recordCommit, exports their actual public operations and supplies preparation to continuation. draft_recovery retains worksheets and backup/restore UI; it no longer owns publication. Existing confirmation, helper, filing, snapshot and immutable receipt authority remains unchanged.

correction_preparation.createCorrectionPreparation owns correction comparisons, eligibility/type checks, visit patches/checks and retained snapshot preparation through six lazy inputs and direct current record facts. correction_workflow.createCorrectionWorkflow owns opening and issuing through 18 scoped adapters. Core composes and exports the actual operations; history presentation, record actions and saved-import work remain in issuance_and_corrections. Shared confirmation/helper/immutable PDF authority remains in existing owners. Neither constructor starts Writer/DOM services or listeners.

workspace_database.createWorkspaceDatabase owns idb/idbGet/idbSet through IDB_OK/indexedDB getters. draft_persistence.createDraftPersistence owns draftBundle/saveDrafts/restoreDrafts through ten scoped adapters. Core composes them after correctionWorkflow, exports their actual functions and supplies their database/UI/backup operations lazily. case_files retains startup locking/restoration order, shared/pending case-file coordination and save-status UI; workspace_shell retains case merge/load/rollback, folder and helper coordination. No constructor starts storage, timers or listeners. Debounce remains in case_files and dispatches to the current composed save operation. Stored database keys, bundle shape, restoration barriers and save/backup order remain unchanged.
